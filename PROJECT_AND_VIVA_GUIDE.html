4. Complete Viva Voce Questions & Model Answers

Q1: What is JDBC and what steps are needed to connect Java to MySQL?
Answer: JDBC (Java Database Connectivity) is a standard Java API that connects Java applications to relational databases. The 5 steps are: 1. Load JDBC driver (com.mysql.cj.jdbc.Driver). 2. Establish connection via DriverManager.getConnection(url, user, pass). 3. Create PreparedStatement with SQL query. 4. Execute query using executeQuery() for SELECT or executeUpdate() for INSERT/UPDATE/DELETE. 5. Process the ResultSet and close resources.
Q2: Why did you use PreparedStatement instead of Statement?
Answer: - Security: PreparedStatement automatically escapes user input, making the application immune to SQL Injection. - Performance: The SQL statement is pre-compiled by the database engine, speeding up repeated execution. - Cleanliness: Avoids cumbersome string concatenations for numbers and strings.
Q3: How is incremental ('Then and Now') marks entry handled?
Answer: In AcademicDAO.java, we use the MySQL INSERT ... ON DUPLICATE KEY UPDATE statement. When marks are entered in phases (CIA1 in mid-semester, CIA2, Assignment, and finally ESE post-semester), existing records are updated seamlessly without data loss or duplicate primary key errors.
Q4: How does the system implement the KEC R2024 Attendance gate?
Answer: When evaluating a course in AcademicDAO, the system computes (attended_classes / total_classes) * 100. If attendance is less than 65%, the student is automatically assigned the SA grade with 0 Grade Points and marked FAIL, overriding any internal marks earned.
Q5: What is the DAO Design Pattern and why did you use it?
Answer: The Data Access Object (DAO) pattern isolates the data persistence layer from business logic and user interface. If the database engine ever changes, only the DAO classes require modification, keeping MainApp.java completely decoupled and unchanged.
